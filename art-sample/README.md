# 苔石哨所 · 本地美术样板 0.1

基线：公开仓库 anjaymi/block-dungeons，提交 `d5279aa053344151ef6cd222ddb00ea12509a696`，2026-10-03 获取。

## 打开

推荐：解压后，用你已有的本地项目静态服务器打开根目录 `moss-outpost.html`。若电脑已经有 Python，可在解压目录运行 `python -m http.server 8000`，访问 `http://localhost:8000/moss-outpost.html`；不要求为了本样板安装新依赖。

可选但尚未实机验证：直接双击 `moss-outpost.html`。静态检查确认所有脚本为随包本地经典脚本，没有应用层 fetch/动态 import/ES module，角色贴图为内嵌 data URI，没有外部 CDN 请求；因此没有发现必须使用 HTTP 的加载机制，但仍不能保证所有浏览器的 file:// 策略及 WebGL 行为。

- 自动进入固定种子的第一层起始房间，作为“苔石哨所”视觉试验区
- “同种子原版”切换相同布局的原渲染对照；切换会重开本次试玩
- H 收起/恢复 HUD 与样板工具条
- WASD 移动，左键攻击，右键射箭，Shift 翻滚，Esc 暂停，I 背包
- “重置场景”有确认框，取消不清空当前局

## 这一版做了什么

1. 起始房间及接壤边缘采用三类地表：中轴灰绿石路、次级旧石面、边缘成片苔藓；矮草块不改变碰撞
2. 该房间附近的墙体采用暗蓝灰侧面、较亮压顶、苔藓冠部和少量垂苔，保留原墙高与遮挡通路
3. 样板使用较冷的环境光、较收敛的暖色火把、较弱角色补光，减少大面积灰雾与光柱；这一照明设置在样板第一层漫游时继续有效
4. 提供独立偏好存储命名空间，音量和外观操作不覆盖原入口的设置

## 保留范围

原 `block-dungeons.html`、`world3d.js`、`scenefx.js`、`sfx.js`、`weapon-gameplay.js` 及其他原仓库文件均未修改。样板从原 HTML 生成，复用同一份角色、攻击、碰撞、装备、掉落与地图流程；没有接入或改写武器实验模块。不是新关卡布局，也没有截断原层路线，玩家可以继续走出样板房间。

改动仅存在于 `moss-outpost.html` 和 `art-sample/`。源码保存在独立 `art/moss-outpost-local` 分支。线上试玩发布方式：仅将本样板的新增文件放入 main，沿用现有 Pages 构建，使用独立 `/moss-outpost.html` 路径；不改默认入口及原游戏文件，不合并整条支线。新增文件会被原仓库根目录的宽泛 .gitignore 规则忽略；这次保持该规则原样。

## 已验证

- 原武器测试 45/45 通过（结果见 `test-results.txt`）
- 新生成 HTML 的内联 JavaScript 语法通过
- 10 个关键游戏流程源码段与原版完全相同
- World3D.decorate 对碰撞格与房间 tiles 的修改逻辑完全相同
- 使用实际体素模型库构造 9 种地表、6 种墙体变体：顶点/法线/颜色均为有限值，高度范围合法
- 在模拟 DOM、未启动 WebGL 的 Node VM 中执行实际 startGame/genFloor/装饰：相同种子的 9,350 格碰撞数组与起始玩家状态完全一致；没有偏好写入

## 还没有验证，不能据此宣称视觉完成

当前云环境阻止本地 Chromium 创建 socket；支持的云浏览器访问本地地址亦被客户端阻止。因此没有成功运行真实 WebGL 帧、没有本版前后截图，也没有完成实际移动/攻击/遮挡/帧率/手机布局验收。

VM 测试模拟了 DOM 和 WebGL 初始化状态，仅证明生成与初始化脚本逻辑，不证明真实浏览器渲染正常。`qa.cjs` 为可选真实浏览器检查脚本，需要用户环境安装 Playwright 并有 Chromium；其输出中的 WebGL 信息必须来自真实浏览器才有效。

下一步最小验收：在能运行原游戏的浏览器打开本包入口，看起始房间是否正常；切换原版比较；移动贴墙、攻击、打开/关闭背包、暂停/继续、重置取消/确认。按 F8 查看 renderer 诊断，确认不是静默回退到 2D。视觉强度和资源密度待实机截图后调整。
