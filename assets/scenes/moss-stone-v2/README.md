# 苔石地牢地面 v2 · 概念落地

本版根据用户选定的 `floor-concept.png` 调整地面破损。完整大石板承担主要行走区域，局部凹入的崩边和缺角露出压实土层，小碎片留在对应破口内。两种破损各有三个轮廓变体；墙边形成不连续的局部损坏区，柱脚偏向一侧，不围成整齐一圈。门前、出口与一格窄通道保留完整石板。

`scene-assets.js` 是游戏与原生模型的几何权威源，`floorTreatment` 根据地图决定类型、方向与稳定变体；地图生成和碰撞不参与修改。运行时继续使用原 GPU 地形合批与顶点颜色，不逐帧读取 bbmodel，也不改变角色贴图或 shader。现有墙体、柱台和墙边碎石几何延用上一版。

`moss-stone-v2.bbmodel` 由 Blockbench 5.2.1 / MCP 1.10.0 原生创建、导出，再在独立项目重导入。含 66 个网格、1 张自制 128×16 调色板：九块地面预览展示三类石板各三个变体，另有墙、柱和碎石预览。`native-front.png`、`native-rear.png` 与 `native-reimport.png` 为真实原生离屏截图；导出前与重导入后的同相机截图像素相同。

`source-layout.json` 保存网格、预览偏移、面色块与原生顶点 / 面键。Blockbench 的随机顶点键有时是纯数字，检查必须使用记录的键序，不能依赖对象枚举顺序。游戏使用单素材局部坐标，不使用预览偏移。游戏坐标每格 24 单位、X/Y 水平、Z 向上；原生转换为 `[x,z,-y]`，编解码保留五位小数。

石板最高点仍为 0，土层最高点为 -1.45，掉落碎片从土层顶面开始且最高点低于 0。每个实体闭合、法线向外，凹形顶面通过三角化生成，不用贯穿整块的长槽模拟破损。碎片完整占地不与残存石板重叠。

执行 `node tests/build-scene-assets.cjs` 可生成调色板、源布局和 MCP 输入；随后需要重新原生创建 / 同步、导出和核验，并写回原生键，才完成 bbmodel 更新。游戏修改与原生编辑都须同步至几何权威源，避免两份模型脱节。`node --test tests/*.test.cjs` 当前 166 项通过；其中 13 项核对场景几何、分布、保护区域、原生导出与贴图。

固定房间前后对照位于 `assets/render-qa/floor-damage-v2/`，访问 `/tests/floor-damage-review.html?version=after` 可切换上一版与本版。固定房间不是用户当前随机地图；实际 PC / 手机布局另有截图。概念图的细微表面纹理尚未完整实现，本版主要完成破损造型、露土与摆放，保留原有石材明暗。真实手机帧率与触屏手感仍需实机验证。

后续按用户要求加入 `stone-material.js`：运行时石材呈现哑光斑驳、细颗粒、浅凹凸与更暗的倒角，世界坐标采样避免逐格重复，屏幕占地过滤减少小屏闪烁。此 shader 不写入原生调色板，bbmodel 的几何、UV 与贴图继续沿用。最新 GPU 表面对照及实际布局截图在 `assets/render-qa/stone-shader/`，不应将原生平色截图当作 shader 效果。几何阶段的对照页面使用保存的着色前源，避免后续材质修改混入旧检查。
