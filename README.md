# 方块暗黑肉鸽 · Block Dungeons

Three.js 体素风俯视角暗黑肉鸽。HTML 入口，无需构建。

**在线试玩：** https://anjaymi.github.io/block-dungeons/

## 操作
手机首页右上角点「全屏游戏」，进入冒险后可点地图右上角的「全屏 / 退出」。支持的浏览器隐藏导航栏并尝试横屏，退出后归还方向锁；手机地址栏、横竖屏和刘海安全区变化会同步更新游戏与触控坐标。

iPhone 可在 Safari 点「分享 → 添加到主屏幕」，保留「作为网页 App 打开」，以后从主屏幕的游戏图标全屏启动。页面会在浏览器不支持一键全屏时显示这段指引。武器实验室的内嵌游戏也允许全屏。

手机左侧摇杆内圈走路，推到外圈奔跑，回到内圈或松手停止奔跑；奔跑仍消耗耐力，摇杆下方显示状态和耐力。右侧可直接攻击、翻滚、跳跃、喝药、使用职业技能和法术，跳跃后按攻击可下砸。「更多」保留三件神器、弓箭与换组。

手机靠近免费装备时，落地后自动收进背包，并显示拾取反馈。绿宝石、箭矢、卷轴和生命补给继续自动收集；商品显示价格并单独点按购买。背包满时只提示一次，剩余掉落留在原地，空出空间后会继续自动拾取。主动丢弃的物品保留点按「拾回」，避免刚丢掉又自动收回。靠近符印、祭坛或出口时，右下角显示对应交互动作。PC 保持 F 手动拾取。

- WASD 移动 · 左键连击 · 右键射箭 · R / 中键魔法 · 空格跳跃
- Shift 翻滚 / 按住奔跑 · Q 职业技能 · 1 2 3 神器 · 4 5 6 法师技能
- E 药水 · F 拾取 · I 背包 · M 地图 · X 换武器组 · Alt 显示掉落 · N 静音 · [ ] 音量

## 第二轮性能优化 · 2026-10-04

以第一轮完成后的版本作为新基线，再优化怪物密集时的绘制。角色和怪物的完整方块骨骼合并为一次显卡绘制，进入共享图集后按原画布顺序合成；贴图、眨眼、受击与冰冻变色、地形高度、脚底阴影、倒地透明度及半透明墙体继续使用原来的规则。图集按实际尺寸扩容，有明确容量上限；超出容量或显卡材质失败时恢复原画布绘制。角色合批独立于地形，上下文丢失时仍可保留其他画面。显卡对象创建使用独立随机来源，避免消耗游戏的随机序列。

同一台 RTX 3070 Ti 的桌面浏览器，固定 1280×720、像素比 1、种子 7319、普通／体素怪物各半。每档预热 15 帧，再采样 120 帧；每个画面帧继续运行两次 120 Hz 战斗模拟。下表按**实际帧间隔的平均值**计算帧率，包含掉帧。

| 同屏怪物 | 本轮开始前 | 本轮优化后 | 本轮提升 |
| --- | ---: | ---: | ---: |
| 96 | 9.4 FPS | 45.3 FPS | 4.8 倍 |
| 192 | 5.0 FPS | 25.4 FPS | 5.1 倍 |

96 怪物的较慢帧间隔（95 分位）从 133.3 ms 降到 33.4 ms；逻辑与绘制的中位耗时从 54.3 ms 降到 21.2 ms。192 怪物仍会降至约 25 FPS。帧率提升超过这次四倍目标，96 怪物的 CPU 耗时改善约为 2.6 倍；不能把这两个指标混为一谈，也不代表所有设备和关卡都会同样提速。

215 项自动检查通过，新增覆盖骨骼与高度、皮肤面映射、眨眼、状态色、透明度归属、旋转包围盒、图集容量、画布恢复、显卡编译失败回退及游戏随机序列。打开[第二轮对照与复测](http://127.0.0.1:8000/tests/performance-round2-review.html)可复测；完整新基线快照、原始帧数据、截图及源码摘要保存在 `assets/render-qa/performance-round2/`，最终数据为 `comparison.json`。内嵌页面的复测可能受额外合成开销影响。

## 第一轮怪物密集场景性能优化 · 2026-10-04

本轮先完成性能优化。后续地图方向调整为更广阔的横向区域，连接野外路线、据点与地下城；大地图本身尚未实现。

主要瓶颈是体素怪物表面的逐格细纹绘制。细纹与边缘明暗改为有容量上限的复用材质，保留实时面光照、受击／冰冻着色和动画；细纹采用八种预烘焙变体与分级亮度。重建体素模型时记录原始外表面，跳过壳体内部接缝面。屏幕外怪物和尸体不构建模型，重新进入画面后恢复绘制，模拟仍继续。怪物避让、唤醒、攻击仲裁与碰撞使用局部空间索引；跨格移动、推挤和召唤即时更新，保持原来的处理顺序。

同一台 RTX 3070 Ti 设备的桌面浏览器中，固定种子 7319、1280×720、普通／体素怪物各半、预热 10 帧后采样 30 帧。角色生命提高以维持压力场景，怪物数量及战斗模拟保留。按浏览器帧间隔中位数计算：

| 同屏怪物 | 优化前 | 优化后 | 帧率提升 |
| --- | ---: | ---: | ---: |
| 24 | 3.3 FPS | 30.0 FPS | 9.0 倍 |
| 48 | 1.9 FPS | 20.0 FPS | 10.3 倍 |
| 96 | 1.0 FPS | 12.0 FPS | 12.4 倍 |

三档场景均超过本轮的四倍目标；对照页内嵌预览另测得 96 只怪物约 7.5 FPS。极限密集场景仍未达到流畅帧率，结果也会随浏览器展示方式和负载变化。这些数据是当前设备的压力场景结果，不代表所有设备或所有关卡。203 项自动测试通过，新增检查覆盖碰撞等价性、跨格邻居、绘制剔除、材质复用及外表面掩码。

打开[性能对照与复测](http://127.0.0.1:8000/tests/performance-review.html)，可选择怪物数量与版本，直接复测。优化前的完整脚本快照、原始帧数据、截图和源码摘要在 `assets/render-qa/performance/`；最终对照数据为 `comparison.json`。测量完成后检查预览已恢复正常新冒险，压力场景只由测试入口载入。

## 地牢目标与祭坛挑战 · 2026-10-04

默认游戏与武器实验室现已接入「清理主路守卫 → F 点亮符印 → 击败出口守卫 → 解除封印进入下一层」的完整任务流程。普通楼层需要两枚符印，首领楼层只需要其主路上的一枚。地图用 ◇ / ◆ 标识未点亮／已点亮的符印；任务面板显示实时进度。旧局刷新后开始新冒险即可使用。

每层另有一条可选祭坛支路，靠近后按 F（手机点击交互）开始两波守卫挑战。祭坛提前 1.2 秒显示地面光圈，再释放脉冲；离开范围、跳跃或翻滚无敌均能躲避。清理后解除房间封锁，发放两个宝箱与额外战利品。挑战和奖励不能重复触发。起点旅途石可在需要时恢复生命、药水和至少 20 支箭，每层只使用一次，满补给不会消耗。

新增旅途石、符印台、双柱祭坛和封印出口拱门。五种主题分别配有苔藓、木架、冰晶、余烬裂光与日轮刻纹，结构随真实地面高度与房间遮挡排序绘制。空中下砸补上墙体、悬空目标和平台高度检查，范围使用发起攻击时的装备快照。

本轮把官方介绍的[探索、任务与跳跃战斗方向](https://www.minecraft.net/en-us/article/minecraft-dungeons-ii-gameplay-systems)转化为本项目的符印任务与祭坛规则；当前仍是五种主题的单人楼层冒险。195 项自动测试覆盖新增主线、祭坛、脉冲躲避、补给、换层和既有战斗／背包／地图逻辑。浏览器截图在 `assets/render-qa/dungeon-journey/`，包含五种祭坛、出口、任务面板与手机布局。截图为指定房间状态的检查；手机检查在桌面浏览器中进行。

## 武器实验室 · 2026-10-03

在仓库目录运行 `node tests/serve.cjs`，打开 <http://127.0.0.1:8000/weapon-lab.html>。默认游戏入口为 `/block-dungeons.html`。

第二击后松开攻击约 0.14 秒，看到角色旁的“变招就绪”后再按攻击。窗口从第二击后摇开始，约 0.85 秒后失效；持续按住仍走基础连段。手机沿用攻击按钮。

- 巨剑「破阵重劈」：跳过旋风，窄线重劈前方；不追加环形震波。
- 双镰「勾回剪击」：选前方最近目标，最多拉近轻敌 1.5 单位再剪击。墙、箱子、玩家和其他敌人会阻挡；重敌不能拉动。
- 战锤「撞阵横砸」：打飞幸存轻敌，最多 2.8 单位。撞墙、箱子或另一敌人只追加一次碰撞伤害，不传播打飞。

Boss、树人、幽灵、传送敌人和离地目标不参与新增位移。实验入口可预选三种武器，正在冒险时重新选择会先提示结束当前局。其他武器沿用基础连段。

默认入口也包含战斗正确性修复：匕首流血与装备伤口独立计时；状态伤害只在游戏运行时推进；死亡奖励只结算一次；按住与点击遵守相同的最短恢复；法杖普攻接入奥能共鸣，齐射共用一次消费标记；攻击及法杖弹体使用发起装备的 UID 与伤害属性；换组和打开背包等待合法恢复点；手机近战使用同一刀身判定。

本次调整会影响真实攻击节奏，未用额外增伤抵消恢复时间。巨剑和战锤的最短接招恢复为 0.10 秒，双镰 0.07 秒，变招 0.18 秒；攻速继续缩短前摇和判定阶段。返回默认入口会关闭三种变招，保留正确性修复。

## 场景与角色视觉优化 · 2026-10-03

苔石地牢取消整块地砖上散落的绿色立方体，使用三个复用的低矮苔藓 / 蕨叶模型，按世界坐标在墙根成簇分布，中央、单格通道、门和出口保持留白。密度变化保留已有候选的位置、大小和方向；模型连同叶尖纳入占地检查。石板墙脚的渐暗与冷色变化在建图时烘焙进顶点颜色，继续沿用分块合批。

地牢角色按面朝向接受环境光与火把光；冰霜、治疗、爆炸和金色光效短暂照亮附近角色，随原光效寿命消退。隔墙光源不参与角色受光，冰冻和受击色调优先，背包及选角保留独立预览光。武器只为金属面增加朝向高光，模型和皮肤数据保留。冰霜冲击的中心亮斑收为透明冷光与细边，保留扩散环和冰片。火把光晕、地牢雾和灰尘收紧，让石材与角色轮廓更清楚。

散布与光照规则归 `scene-style.js` 所有；GPU 地形和 Canvas 角色共用世界坐标，不改写地图或战斗判定。`node tests/render-scene-style.cjs` 生成实际角色贴图 / 武器的环境光检查图与低、中、高密度摆放图，位于 `assets/render-qa/scene-character/`；同目录 `browser-*.jpg` 是实际浏览器截图。真实手机帧率与触屏手感仍需设备检查。

## 角色战斗动态 · 2026-10-04

巨剑和战锤增加后坐蓄力、躯干前送、支撑脚换重心与扶柄手跟随；战锤重击带动身体下压。双镰交替挥砍时另一只手保持守势，旋身时脚步随转动交换支撑。剪击蓄力到出手的小幅腕角跳变已修平。起手、连续接招和收势到真实待机 / 行走之间增加短衔接，转身取最短角度并在有效出手前完成。

`combat-motion.js` 独立拥有显示姿态和每个角色的衔接状态，原刀身判定、攻击时间、伤害和移动逻辑继续沿用。世界角色及头发 / 围巾的附属摆动使用模拟时间，暂停和命中停顿不推进；附属摆动读取真实行走速度与旋风角速度。选角和背包保留独立呼吸，换武器与翻滚清掉旧动作衔接。

`node --test tests/*.test.cjs` 为 153 项通过。新增检查覆盖阶段连续性、高攻速真实命中与位移一致、短蓄力、长帧、暂停、换武器及预览状态独立。`node tests/render-combat-motion.cjs` 生成原生 Canvas 动画 `assets/render-qa/combat-motion/three-weapons.gif` 和姿态表；同目录浏览器截图记录实际 GPU 地牢中的 PC / 手机布局。动画使用生产角色、皮肤和武器，不是 GPU 录屏；手机验证仍需真机体验。

## 大石板与建筑层次 · 2026-10-04

苔石地牢的密集小地砖换成大块倒角石板，保留少量缺角、斜裂缝和破角，完整铺底仍处于角色地平面以下。墙体改用三层大石块、墙脚与四块分割压顶，间隔设置壁柱；独立石柱增加分层柱台、柱帽和细铜饰带。墙边新增小碎石，出口附近保持留白。现有苔藓散布、角色及战斗链路继续沿用，其他四个主题保持原资源与光照。

共享程序模型位于 `scene-assets.js`，原生 Blockbench MCP 制作、导出和重新导入检查的可编辑素材在 `assets/scenes/moss-stone/moss-stone.bbmodel`。调色板、构建数据、正背面截图及检查记录在同目录。`node tests/build-scene-assets.cjs` 可重新生成素材源数据；游戏继续使用原地形合批，不逐帧解析原生模型。

## 石材表面 shader · 2026-10-04

用户进一步要求减少石块的玩具感，新增 `stone-material.js`，仅供这批共享石板、石墙、石柱与碎片使用。原有 Lambert 灯光与阴影保留，表面增加稳定的世界坐标斑驳、细颗粒、浅凹凸与矿物色差；斜面倒角压低亮度，石材不使用原普通道具的脉动边缘辉光。细颗粒按屏幕像素占地淡化，缩小或移动镜头时减少高频闪烁。

本轮不修改原生几何与贴图，bbmodel 继续交付造型；程序 shader 是游戏运行时的材质，Blockbench 截图不等于此表面效果。`tests/stone-material-review.html` 提供着色前 / 后的同场景 GPU 对照，实际电脑和手机布局截图保存在 `assets/render-qa/stone-shader/`。当前 170 项检查通过。固定房间三角形保持 82,116，独立石材材质使批次由 10 增至 16；没有测量或宣称 FPS 改善。
